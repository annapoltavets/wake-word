# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Scope

This directory is one independent PlatformIO + ESP-IDF project inside the Module_6 coursework repo (sibling directories are unrelated projects with no shared code). Target: `esp32-s3-devkitc-1`, plain C (`.c`, not C++ like the older `M_6_1_*` projects), pinned `espressif32@6.8.1` / `framework-espidf@3.50301.0`.

## Commands

Run from this directory with the PlatformIO CLI:

```bash
pio run                       # build
pio run -t upload -t monitor  # flash, then open serial monitor (115200, exception decoder on)
pio run -t clean
```

No tests or lint tooling exist. `sdkconfig.esp32-s3-devkitc-1` is generated by the build; don't hand-edit it. `src/CMakeLists.txt` globs everything in `src/`, so new files are picked up without registration.

## Architecture

Pipeline of three FreeRTOS tasks: microphone → `audio_task` → `audio_queue` → `inference_task` → mutex-protected LED state (`led_set_state`) → `led_task` (woken by task notification).

- `audio.{c,h}`: I2S RX (INMP441-style mic, 16 kHz, 32-bit slot, left channel) on GPIO 4/5/6 (BCLK/WS/DIN). `audio_task` reads 512-sample (32 ms) frames, converts 32-bit → 16-bit with `>> 14` plus clamping, and pushes `audio_frame_t` to `audio_queue` (depth 8, non-blocking send; drops frames with a warning when full).
- `wake_word.{c,h}`: classifier interface. `wake_word_process()` takes a `WW_WINDOW_SAMPLES` (1 s, 16000) window and fills `ww_result_t` (`WW_NONE/ON/OFF/TOGGLE` + score vs `WW_THRESHOLD`). **The real model is not integrated yet**: `WW_USE_ENERGY_STUB 1` substitutes an RMS-loudness check on the last 0.25 s that always returns `WW_TOGGLE`. The real path (TFLite Micro, MFCC features, tensor arena) is the `#else` branch and `wake_word_init()`, both marked TODO.
- `main.c`: `inference_task` keeps a 1 s sliding window (`memmove` + append each frame), runs inference every `HOP_FRAMES` (8 frames = 256 ms), and after a detection skips `COOLDOWN_FRAMES` (31 ≈ 1 s) of inference. Maps labels to `led_cmd_t` and calls `led_set_state()`.
- `led.{c,h}`: the LED level is a static shared variable guarded by a mutex. `led_set_state()` (ON/OFF/TOGGLE, read-modify-write under the mutex) then notifies `led_task`, which reads the level under the mutex and drives GPIO 15. There is no LED queue.

Task placement is deliberate: `audio_task` (prio 6) and `led_task` (prio 4) are pinned to core 1; the heavy `inference_task` (prio 5, 8 KB stack) is pinned to core 0 so inference never starves I2S reads. Keep that split when adding work.

## Gotchas

- The frame size/hop/cooldown constants in `main.c` assume 512-sample frames at 16 kHz (`AUDIO_FRAME_SAMPLES`, `AUDIO_SAMPLE_RATE` in `audio.h`); change them together, and keep `WW_WINDOW_SAMPLES` matching the model's expected input.
- `audio_queue` and the LED mutex are created in `audio_init()` / `led_init()`; both must run in `app_main` before the tasks are created.
- `platformio.ini` sets 16 MB flash and octal PSRAM, but `board_build.extra_flags` is not a standard PlatformIO option for ESP-IDF, so the PSRAM define may not take effect. PSRAM is controlled through sdkconfig, so check there before relying on it (e.g. for a tensor arena).
- Comments are mostly Ukrainian; match the language of the surrounding file. Code uses tab indentation and Allman braces.
